ระบบบริหารจัดการรายรับอัจฉริยะ (Income & Sales Management) ต่อยอดจากระบบเบิกจ่าย IOU Phase 1 — อ้างอิงจาก DOC-001 Smart_ERP_Blueprint.pdf และ DOC-002 สรุป.docx

Tip: ทุก ID ในเอกสารนี้เชื่อมกันแบบ Bidirectional — วางเมาส์บนชิป/ป้ายสีใดก็ได้เพื่อดูว่า ID นั้นถูกอ้างถึงตรงไหนบ้างทั่วทั้งหน้า โดยเฉพาะแถบ "chain" สีในการ์ด Use Case ที่แสดงเส้นทางเต็มตั้งแต่ Workflow จนถึง Test Case

0. Executive Overview

DOC-001 Smart ERP: พิมพ์เขียวสถาปัตยกรรมการเงินระดับองค์กร

ที่มา: Smart_ERP_Blueprint.pdf (Confidential Internal Document, เมษายน 2567)

สรุปโครงสร้างระบบเบิกจ่าย (Phase 1 — 90% Completed), ระบบฝั่งขาย (Phase 2 — In Development) และเป้าหมายบูรณาการข้อมูลเพื่อผู้บริหาร (The Vision).

DOC-002 เอกสารสรุปข้อมูล: โครงการพัฒนาระบบบริหารจัดการองค์กร Phase 2

ที่มา: สรุป.docx

เป้าหมายหลัก: ขยายขีดความสามารถจากระบบบริหารรายจ่าย (Phase 1) ไปสู่ระบบบริหารรายรับและกระแสเงินสด (Phase 2) แบบเต็มรูปแบบ ตั้งแต่ต้นน้ำ (ใบเสนอราคา) ถึงปลายน้ำ (รับเงิน + กระทบยอดธนาคาร) โดยใช้ฐานข้อมูล SQL เดียวกันกับ Phase 1 (Single Source of Truth) และวางแผนให้โมดูลหลัก (ใบเสนอราคา + สายอนุมัติ) แล้วเสร็จภายใน 1-2 เดือน โดยเริ่มจากบริษัท ACE Part เป็นลำดับแรก

Companies in scope (หัวเอกสารที่ต้องสลับได้): ACE Part, Smart, Flow

1. Workflows (WF-001 – WF-005)

WF-001 ระบบเบิกจ่าย IOU & Expense Management Phase 1 — 90% / Reference

ควบคุมการนำเงินออกจากบริษัทผ่านฐานข้อมูลเดียว (IOU Core Database) ครอบคลุม Master Data, IOU & Advance, Travel Expense, Document Tracking. เป็นฐานข้อมูล (Base Layer) ที่ Phase 2 เรียกใช้ร่วมกัน

Contains UC-001 UC-002 UC-003

อ้างอิง: DOC-001 หน้า 2-3, 5

WF-002 วงจรเอกสารฝั่งขาย (Sales Document Cycle) Phase 2

กระบวนการต้นน้ำถึงปลายน้ำของฝั่งขาย: ใบเสนอราคา → สัญญา → ใบส่งมอบงาน/ใบแจ้งหนี้/ใบวางบิล → ใบกำกับภาษี → ใบลดหนี้ → ใบเสร็จรับเงิน ข้อมูลไหลต่อกันเป็นสายน้ำเดียว ลดการคีย์ซ้ำ และดึง Master Data จาก WF-001 มาใช้ร่วมกัน

Contains UC-004 UC-005 UC-006 UC-007 UC-008 UC-009 UC-010

อ้างอิง: DOC-001 หน้า 6-10, DOC-002 หัวข้อ 2.1

WF-003 ระบบอนุมัติกลาง (Central Approval Workflow) New / Cross-cutting

Approval Service ส่วนกลางที่ทุกโมดูลของ ERP เรียกใช้ร่วมกัน สายอนุมัติกำหนดผ่าน Database Config เพื่อรองรับ Business Logic ที่แตกต่างกันของแต่ละบริษัทในเครือ (PM → MD → Account → Head Account / CEO) โดยไม่ต้องแก้โค้ดใหม่ทั้งหมด

Contains UC-013 UC-014

อ้างอิง: DOC-001 หน้า 4, 13, DOC-002 หัวข้อ 3.2

WF-004 กระทบยอดธนาคารและแดชบอร์ดผู้บริหาร The Vision

เป้าหมายสูงสุด: กระทบยอดบัญชีอัตโนมัติ (Automated Bank Rec/ROV) แบบ Line-by-Line ระหว่างข้อมูลระบบกับ Bank Statement พร้อม Cash Flow Dashboard สำหรับผู้บริหาร

Contains UC-015 UC-016 UC-017

อ้างอิง: DOC-001 หน้า 2, 11-12, DOC-002 หัวข้อ 2.2

ความสามารถเชิงเทคนิคที่รองรับ WF-002: Dynamic Form Generator สำหรับสลับหัวเอกสาร/เทมเพลตตามลูกค้าแต่ละราย (เช่น การรถไฟ) และระบบจองเลขที่ใบกำกับภาษีล่วงหน้าเพื่อรักษาลำดับเลข-วันที่ตามกฎสรรพากร

Contains UC-011 UC-012

2. Use Cases (UC-001 – UC-017)

แถบสี "chain" ด้านล่างของแต่ละ Use Case คือเส้นทางความเชื่อมโยงแบบเต็ม: Workflow → Use Case → Screen → API → Test Case

UC-001 จัดการข้อมูลหลัก (Master Data Management)

Actor: Admin / Account — จัดการข้อมูลโปรเจกต์ (Project-based Accounting), รายชื่อพนักงาน, สิทธิ์การใช้งาน และคู่ค้า (Supplier/Customer) เป็นฐานข้อมูลกลางที่ WF-002 เรียกใช้ร่วมกัน

WF-001→ UC-001→ SCR-001→ API-001→ no TC yet

UC-002 ติดตามหนังสือค้ำประกันธนาคาร (LG Management)

Actor: Account — ติดตามวันหมดอายุของหนังสือค้ำประกัน (Letter of Guarantee) สำหรับงานราชการ และเชื่อมโยงค่าธรรมเนียมธนาคารเข้าเป็นรายจ่ายบริษัทโดยอัตโนมัติเมื่อถึงกำหนด

WF-001→ UC-002→ SCR-002→ API-002→ no TC yet

UC-003 จัดทำงบประมาณโครงการ (Project & BOQ Management)

Actor: PM — ทุกการเบิกจ่ายต้องผูกกับเลขโปรเจกต์เพื่อควบคุมต้นทุน (Cost Control) เทียบกับแผน BOQ/BOM ป้องกันงบบานปลาย

WF-001→ UC-003→ SCR-003→ API-003→ no TC yet

UC-004 สร้างใบเสนอราคา (Create Quotation)

Actor: PM / Account (ACE Part เป็นบริษัทนำร่อง) — จุดตั้งต้นของข้อมูลฝั่งขาย เลือกเทมเพลตมาตรฐานหรือซับซ้อนตามลูกค้า (ดู UC-011)

WF-002→ UC-004→ SCR-004→ API-004→ TC-001

UC-005 ต่อรองราคาและบันทึกประวัติ (Negotiate & Track Quotation Revisions)

Actor: PM / Account — เก็บประวัติการแก้ไขราคาหลายเวอร์ชันจนถึง Final Price และสถานะการประมูล (ชนะ/แพ้) ซึ่ง Final Price จะกลายเป็นราคาตามสัญญา

WF-002→ UC-005→ SCR-004→ API-004→ TC-002

UC-006 แปลงใบเสนอราคาเป็นสัญญา (Convert Quotation to Contract)

Actor: Account — คีย์ราคาและรายละเอียดไอเทมตามสัญญาโดยอ้างอิงราคาสุดท้ายจากใบเสนอราคา เพื่อใช้เป็นฐานข้อมูลวางบิล

WF-002→ UC-006→ SCR-005→ API-005→ TC-003

UC-007 ออกใบส่งมอบงาน / ใบแจ้งหนี้ / ใบวางบิล

Actor: Account — เลือกออกเอกสาร 3 แบบจาก Data Core เดียวกัน (ลูกหนี้+สัญญา+Running Number เดิม) พร้อมเปลี่ยนหัวเอกสารได้ตามบริษัทในเครือ (Configurable Headers) โดยไม่ต้องออกเอกสารซ้ำหลายใบสำหรับงานเดียวกัน

WF-002→ UC-007→ SCR-006→ API-006→ TC-004

UC-008 ออกใบกำกับภาษี (Issue Tax Invoice)

Actor: Account — ขั้นตอนที่ต้องการความเข้มงวดสูงสุด: เลขที่และวันที่ต้องเรียงลำดับต่อเนื่องตามกฎสรรพากร (ห้ามเลขข้าม/ห้ามกระโดด) ใช้ร่วมกับระบบจองเลขล่วงหน้า (UC-012)

WF-002→ UC-008→ SCR-007→ API-007→ TC-006

UC-009 ออกใบลดหนี้อ้างอิงใบกำกับภาษีเดิม (Issue Credit Note)

Actor: Account — ใบลดหนี้ไม่สามารถลอยตัวได้ ต้องมีฟังก์ชันดึงข้อมูลอ้างอิง (Tagging/Linking) กลับไปยังใบกำกับภาษีตั้งต้นเสมอ รองรับทั้งตัดยอดเต็ม (Full Refund) และตัดย่อย (Partial Refund) พร้อมคำนวณยอดคงเหลืออัตโนมัติ

WF-002→ UC-009→ SCR-008→ API-009→ TC-007+TC-008

UC-010 ออกใบเสร็จรับเงิน (Issue Receipt)

Actor: Account — ขั้นตอนสุดท้ายของวงจรเอกสารฝั่งขาย สิ้นสุดกระบวนการฝั่งเอกสารก่อนนำไปสรุปในระบบบัญชีและกระทบยอดธนาคาร (UC-015)

WF-002→ UC-010→ SCR-009→ API-010→ no TC yet

UC-011 เลือก/สร้างเทมเพลตเอกสารแบบยืดหยุ่น (Dynamic Document Template)

Actor: PM / Account — Quotation Engine รองรับ 2 รูปแบบ: Standard Template (หัวบริษัท 6 แบบ) และ Complex Template (โครงสร้างซับซ้อน Text-heavy เช่น แบบฟอร์มการรถไฟ ที่ต้องการ Strict Formatting) ผู้ใช้เลือกฟอร์มได้เองโดยไม่ต้องเขียนโค้ดใหม่

WF-005→ UC-011→ SCR-010→ API-011→ TC-009

UC-012 จองเลขที่ใบกำกับภาษีล่วงหน้า (Pre-book Tax Invoice Number)

Actor: Account — ระบบ Number Booking: ล็อคเลขที่และวันที่ไว้ล่วงหน้า (Locked Placeholder) เพื่อป้องกันการข้ามลำดับ (Strict Sequence) และรักษาความถูกต้องทางบัญชี 100%

WF-005→ UC-012→ SCR-007→ API-008→ TC-005

UC-013 กำหนดค่าสายอนุมัติตามบริษัท/ประเภทค่าใช้จ่าย (Configure Approval Line)

Actor: Admin — ตั้งค่าความยืดหยุ่นของ Line of Approve ผ่าน Database Config เพื่อรองรับ Business Logic ที่ต่างกันของแต่ละบริษัทในเครือ (Smart Business Flow vs ACE Business Flow) โดยไม่ต้องแก้โค้ด

WF-003→ UC-013→ SCR-011→ API-012→ TC-013+TC-014

UC-014 อนุมัติเอกสารผ่าน Approval Service กลาง (Approve Document)

Actor: PM / MD / Account / Head Account / CEO — ทุกโมดูลของ ERP เรียกใช้บริการอนุมัติกลางร่วมกัน เพื่อให้กระบวนการอนุมัติจบในที่เดียว

WF-003→ UC-014→ SCR-012→ API-013→ TC-013+TC-014

UC-015 กระทบยอดธนาคารอัตโนมัติ (Automated Bank Reconciliation)

Actor: Account — Matching Engine เปรียบเทียบข้อมูลฝั่งระบบ (300+ บรรทัด/วัน) กับ Bank Statement (2-3 บรรทัด) แบบ Line-by-Line ให้ยอดกระทบตรงกัน 100% ด้วยการคลิกเดียว

WF-004→ UC-015→ SCR-013→ API-014→ TC-010

UC-016 จัดการค่าธรรมเนียม/ค่าปรับธนาคารอัตโนมัติ

Actor: ระบบ (Automated) — เมื่อธนาคารหักค่าธรรมเนียม ระบบสร้างรายการเบิกจ่าย (IOU Expense) ให้ทันทีโดยอัตโนมัติ รวมถึงจัดการค่าปรับ (Penalties) ฝั่งขาย

WF-004→ UC-016→ SCR-013→ API-014→ TC-011

UC-017 ดูแดชบอร์ดกระแสเงินสดและพยากรณ์รายได้ (Cash Flow Dashboard)

Actor: ผู้บริหาร (Executive/CEO) — ภาพรวมเงินเข้า-ออกทั้งบริษัทในหน้าเดียว, พยากรณ์รายได้ 3 เดือนข้างหน้า ดึงข้อมูลจากฐานข้อมูลเดียว (Single Source of Truth)

WF-004→ UC-017→ SCR-014→ API-015→ TC-012
